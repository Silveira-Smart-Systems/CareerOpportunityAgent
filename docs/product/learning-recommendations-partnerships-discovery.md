# Learning recommendations and strategic education partnerships — Discovery

Status: **Conceptual proposal, no partnership or product approval**  
Tracking: [Strategy issue #87](https://github.com/Silveira-Smart-Systems/CareerOpportunityAgent/issues/87)

## Product opportunity
COA should eventually support explicit user requests for training recommendations to address career goals and skills suggested by opportunities. Potential partners include Pluralsight, Coursera, Udemy and other vetted providers. None are currently verified COA partners.

## Example user flow
1. User asks: “What should I learn to become an Azure Solutions Architect?” or “Which courses would help me qualify for this vacancy?”
2. COA identifies target skills and maps them to verifiable opportunity requirements and user-supplied professional evidence. Any inferred gap is marked as inferred.
3. COA offers a shortlist of learning options, with level, prerequisites, language, workload, cost and provider attribution where confirmed.
4. Explain why each recommendation helps, disclose commercial relationships and show relevant non-sponsored alternatives.
5. User chooses whether to open an external provider link; do not transfer personal profile information or auto-enrol.

## Business hypothesis
Referral/affiliate revenue or negotiated partner arrangements may offset product operating costs. Validate official program eligibility, rates, attribution, territorial rules, promotional restrictions, cancellation treatment, user demand and conversion economics before choosing an approach. No assumed commission rate or guaranteed revenue.

## Product integrity
- Ranking quality must be independent of referral payout.
- Label paid links visibly and consistently, including mobile and accessibility contexts.
- Never claim a course guarantees a job or certification unless substantiated.
- Use current, licensed/authorized catalog metadata with source provenance.
- GDPR/ePrivacy review before any tracking or user data sharing.
- User-requested recommendations first; do not introduce aggressive upsells into opportunity discovery.
- Design for “no good courses found” and “commercial relationship unavailable” states.

## Candidate UX surfaces (Concept A)
- Opportunities detail: optional “Close skill gaps” action.
- Profile/Goals: explicit “Suggest learning paths” request.
- Learning recommendations: explainable course shortlist and transparent sponsored indicators.
- Course comparison: evidence, price, effort, level, language, date checked, provider link.
- Web/Mobile consistency; synthetic course examples only during exploration.

## Discovery phases
D1: User problem, qualitative value and success metrics.
D2: Official partner-program validation and commercial feasibility.
D3: Privacy, ranking integrity and legal/disclosure design.
D4: Web/Mobile UX concept and evidence review.
D5: Go/no-go decision for separately authorized implementation.

No outreach, agreement, API access, personal data transfer, code implementation, merge or deployment is approved by this document.
